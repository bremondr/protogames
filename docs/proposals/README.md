# Proposals

A proposal describes a feature that is **not built yet** in enough detail to decide on it and to write the issue from it. It is not a specification of what the app does today.

| Proposal | Issue | Status | Last verified |
|---|---|---|---|
| [playtest-secret-screens.md](playtest-secret-screens.md): phones as secret screens in playtest, peer to peer, no server | [#116](https://github.com/bremondr/protogames/issues/116) | Not built | 2026-10-26 |

## How a proposal is retired

- **Built:** move what now exists into the matching reference document (for playtest, [../PLAYTEST.md](../PLAYTEST.md); for formats, [../SPECIFICATION.md](../SPECIFICATION.md)), then archive the proposal in [../archive/](../archive/) with a note saying where the real description lives, or delete it.
- **Rejected or dropped:** archive it with the reason, or delete it.
- **Changed while being built:** fix the proposal or retire it; a proposal that disagrees with the code is worse than none.

Each proposal starts with a status line (proposal, not built, issue number) and is listed in the table above and in [../README.md](../README.md).
